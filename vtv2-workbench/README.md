# VTV2 Workbench — исследовательский контроль индекса

Дата публикации: 2026-11-17. Папка сайта: `/vtv2-workbench/`.

## Назначение
Рабочий стол на русском языке для явной проверки полнотекстового каталога VTV2. Авторитетный реестр: частный `paveldubovmy/VTV-COMPACTNESS`, `knowledge_graph/v2/fulltext_manifest.json` (1210 файлов, 81 сегмент), Git source head `5f72553743459e96cb04d8a3b1ffb586c777cf41`. Отдельно зафиксированы 87 узлов, 113 типизированных связей и снимок 20 последних коммитов на дату публикации. Это **статический снимок**, не автоматический GitHub-синхронизатор.

Исходные метаданные находятся в `vault.json` и зашифрованы PBKDF2-HMAC-SHA256 (310000 итераций) + ChaCha20-Poly1305 (RFC 8439). Пароль отсутствует в репозитории. HTML, CSS и JS открыты. GitHub Pages **не предоставляет серверный login**, поэтому ресурс не является полностью закрытым в строгом смысле; слабый пароль может быть подобран офлайн. Для настоящего разграничения доступа нужен отдельный hosting/auth gateway (например, Cloudflare Access на собственном домене).

## Правила достоверности

1. Запись в манифесте дает только статус *требует проверки*, не *проиндексировано*.
2. Статус «проверено» требует совпадения исходного Git blob SHA-1 (вычисленного по реальным байтам) и непустого действительно извлеченного текста. Проверка выполняется локально в браузере, файлы на сервер не отправляются.
3. Для PDF/DOCX, бинарных отчетов и архивов автоматическое текстовое извлечение не заявлено. После проверки исходных байтов нужно импортировать реальный извлеченный текст.
4. Выбор папки checkout для массовой проверки обрабатывает до 300 новых файлов за один запуск, 30 МиБ на файл. При повторном выборе ранее SHA-подтвержденные файлы пропускаются. Большие файлы требуют отдельного ресурсного gate.
5. Поиск в браузере проверяет фактически загруженные тексты. Это отдельный smoke-test, **не** замена реального запуска `search.py` и `tests_v2.py` из V2.
6. Графовые PASS/FAIL/OPEN из научного каталога — исходные claims. Ручная проверка в панели требует отдельного протокола и не повышает научный статус.
7. Новые коммиты и манифесты добавляются вручную; форма на странице не изменяет GitHub, Actions не запускает. Изменения хранятся в зашифрованной локальной контрольной точке браузера и могут быть экспортированы.
8. Все выводы на странице — контроль качества исследования, не физические предсказания; ACTION_SHA=STATE_SHA=NOT_DEFINED.

## Минимальный следующий тест

В локальном checkout выбрать один небольшой текстовый файл, загрузить его через раздел «1 210 исходников», вычислить Git blob SHA и действительно извлечь текст. Затем запустить поиск по этому файлу с предварительно указанным ожидаемым путем. После этого сохранить точку остановки и экспортировать технический отчет.

## Контроль команд (Windows PowerShell)

```powershell
git clone https://github.com/paveldubovmy/VTV-COMPACTNESS.git
cd VTV-COMPACTNESS
py -3 .\knowledge_graph\v2\verify_v2.py
py -3 .\knowledge_graph\v2\tests_v2.py
```

Эти команды приводятся для локальной воспроизводимости. На сервере GitHub Pages они не исполняются.
